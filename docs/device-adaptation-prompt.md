# 给编程 agent 的 Jolt 设备适配提示词

请在我克隆的 Jolt 仓库（我的 fork）里，为我实际连接到 Windows 的设备实现电量读取，完成真机验证并向 `Daieenbo/Jolt` 提交 PR。型号和连接方式以我在对话中提供的信息为准。需要人工操作时，请说明要我做哪一步、观察什么，拿到结果后继续。

## 1. 确认现有表现

从 Jolt 的最新 `main` 建立独立工作分支，保留工作区已有改动。先查 README 的「当前已支持」「已知限制」和 `src/Providers` 中最相近的实现。在仓库根目录用 PowerShell 运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
.\Jolt-Test.exe --test
```

诊断程序只列出现有 provider 发现的设备。若看不到目标，请在设备管理器核对硬件 ID，必要时让我拔插接收器或断开、重连蓝牙，确认哪个接口随之变化。记录完整型号、连接方式，以及可取得的 VID/PID、HID 用途页和用途。若已能正确识别并读数，仅补充缺少的实测型号或连接方式；如果文档也已覆盖，直接报告结果。

## 2. 实现与设备匹配的读取方式

优先复用已有协议。根据目标接口、报告长度和可核实的电量查询或上报样本确定匹配条件，留意共用 VID/PID 的接收器和复合 HID 设备。只使用用途已确认的电量查询，避免试发未知命令。协议证据不足时，列明还需要哪种状态的读数或报告，请我协助采集。

需要新增 provider 时，在 `src/Providers` 实现 `IDeviceProvider` 的 `Name`、`Discover(catalog)` 和 `Read(device)`，并在 `src/Core/DeviceManager.cs` 的构造函数中注册。HID 枚举复用传入的 catalog，读写复用 `src/Interop/HidNative.cs`。为读操作设置有界等待，校验回复的长度、标识和数值范围。在 provider 旁注明已验证的电量字段、单位及充电位。

按 `src/Core/Models.cs` 表达读数。未知百分比用 `Percent = null`，无法判断充电用 `ChargingKnown = false`。如果协议只给档位或电压，说明档位映射或估算依据。检查休眠、超时或接收器缓存旧值时的表现，避免把它们显示为刚读到的在线电量。

## 3. 在手边的设备上验证

重新运行上面的构建和诊断命令，再启动本次构建的 `Jolt.exe` 查看悬停浮层。记录以下观察，把无法测试的项目标为「未测」。

| 操作 | 要核对的结果 |
|---|---|
| 唤醒目标设备 | 名称和通道正确，每台设备只出现一次。将 Jolt 读数与同一时刻厂商软件、Windows 或设备指示灯的读数或档位对照，注明参照来源。 |
| 接上和拔掉充电线（适用时） | 观察连接通道、电量和充电状态。若设备会切换为有线模式，单独记录。 |
| 让设备休眠或关机，然后唤醒；断开再重连 | 区分「接收器仍在」与「接收器已拔掉」，观察刷新后旧值如何显示，以及恢复连接后能否重新读取。 |

记录实际测试的 Windows 版本、型号、连接方式以及能取得的固件版本。若机器上还有其他已支持设备，对比改动前后的诊断结果，检查重复识别或误匹配。只有确认读数的型号和通道才能写入 README 的支持列表。

## 4. 提交 PR 并交付链接

更新 README 的支持表，必要时补充协议说明和已知限制。检查 diff，只提交本次适配相关源码与文档。诊断输出只摘录与目标有关的字段；移除 HID 实例路径、序列号、蓝牙地址及本地用户名。

将工作分支推送到贡献者自己的 Jolt fork，向 `Daieenbo/Jolt` 的 `main` 创建 PR。使用 GitHub CLI 时，推送后可用 `gh pr create --repo Daieenbo/Jolt --base main --head <贡献者账号>:<工作分支>` 显式选定目标。PR 正文列出：

- 设备型号、匹配标识、测试环境和已验证的连接方式。
- 改动前的表现、复用或新增的协议，以及读数或估算的依据。
- 构建命令和结果、真机操作、预期与实测值（例如「厂商软件 72%，Jolt 72%」），以及未测项目和限制。

最后返回实际创建的 PR 链接。若缺少真机反馈，报告已完成的工作及具体待测步骤；若验证完成但无法推送或创建 PR，保留本地提交，给出提交号、目标分支、PR 标题和正文，方便我继续提交。
